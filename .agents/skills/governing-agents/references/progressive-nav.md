# 渐进式导航规范

本文规定入口文档、技能、知识条目与记忆条目的阅读顺序。它只定义组织方法，不替代各文件的领域规则。

## 什么时候使用

新增、重写或明显压缩 `.md`、`README.md` 源片段、技能说明、知识条目和记忆条目时使用。

## 五层结构

按读者需要逐层展开，前一层能让读者决定是否继续读下一层：

1. **定位**：开篇一小段说明「这是什么、为什么存在、对谁有用」，不写历史、进度与流水账动机；纯操作型文件（如索引、速查表）可只用一句话。
2. **找路**：告诉读者常见目标对应的章节、路径或下一份权威文档。
3. **地图**：用目录、流程图或短表格展示组成部分和关系。
4. **执行**：只写本文件负责的规则、流程或事实，不复制其他文件的完整内容。
5. **深入**：把低频细节放到明确命名的参考文件，并提供相对路径。

## 不同文件的重点

| 文件 | 第一问题 | 主体内容 |
| :--- | :--- | :--- |
| `ARCHITECTURE.md` | 这个项目是什么、为什么存在、怎么组成？ | 定位段、人类总览、任务入口、主流程和目录地图 |
| `AGENTS.md` | Agent 必须遵守什么？ | 硬性约束、边界、优先级和最短路由 |
| `.agents/README.md` | 工作区里的内容怎么分类？ | `skill`、`knowledge`、`memory` 与生成物的区别 |
| `SKILL.md` | 什么时候按什么步骤做？ | 适用场景、成功标准、流程、边界和验证 |
| `knowledge/*.md` | 当前稳定事实是什么？ | 参数、来源、路径和适用范围 |
| `memory/*.md` | 过去遇到过什么问题？ | 现象、根因、决策、验证结果和经验 |
| `README.md` | 对外要展示什么？ | 由 Quarto 生成的最终展示内容 |

## 去重判断

- 入口只负责定位和路由，不复制技能正文。
- 索引只回答“在哪里”和“什么时候读”，不复制完整规则。
- 同一规则只能有一个完整定义处；其他位置保留一句摘要和指针。
- 删除前必须确认没有运行入口、CI 依赖、唯一事实价值或仍需保留的历史背景。
- 不能证明无用的内容先列入审计报告，不在平衡清理中直接删除。

## 写作验收

- 读者只看前两段就能判断这份文件是否相关。
- 常见任务最多三次跳转能到达执行细节。
- 每个标题只承担一个问题，列表项保持同一颗粒度。
- 低频细节下沉后，正文仍能独立解释文件职责和边界。
