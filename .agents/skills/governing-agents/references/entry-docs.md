# 入口文档写法

适用于仓库级说明入口：根目录 `AGENTS.md`、根目录 `ARCHITECTURE.md`、`.agents/README.md`、`KNOWLEDGE.md`、`MEMORY.md`、`memory/domains/<domain>/index.md`。不适用于技能正文、知识条目、记忆条目与 README 展示文案。

## 写法约束

- 一条规则一行：一条约束、一个指针各占一行，不把多条塞进同一段。
- 开篇一段定位：用两三句说明「这是什么、为什么存在」，不写历史、进度、流水账动机与举例；纯索引型入口可只写一句用法。
- 不复述技能内容：技能里已有的流程与参数只写指针（技能名 + 技能内相对路径）。
- 不复述彼此：同一事实只在一个入口文档里完整出现，其余位置写指针。
- 面向两类读者：新人靠它找到入口，Agent 靠它确定边界；用完整句子，不用只有作者懂的缩写。
- 顺序固定：用途一句话 → 执行原则 → 隐私与安全 → 硬性约束 → 构建与校验 → 导航指针 → 本机配置（如适用）。
- 单行不超过约 100 字符；长清单改写成指向技能或知识文件的指针。
- 表格只用于「名称 → 路径」类映射，不放长句。
- 不写当前进度、待办、讨论过程与本机个人路径。

篇幅以 `SKILL.md` 的「篇幅预算」表为准，本文件不重复。

## 检查清单

- [ ] 每条约束独立成行，读一行即可执行。
- [ ] 入口文档的指针全部指向真实路径。
- [ ] 只读入口文档即可找到对应技能、知识与记忆。
