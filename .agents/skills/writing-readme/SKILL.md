# Profile README 内容规范

## 适用范围

适用于 GitHub Profile README 和仓库展示页的文案与结构编辑。视觉配色、组件选型与推荐项目列表样式见 `designing-visuals`；措辞、标题与命名见 `writing-chinese`；Quarto 渲染与仓库维护见 `maintaining-readme`；组件信任层级与色板参考见 `.agents/knowledge/KNOWLEDGE.md`。命名、目录结构、AGENTS 类文档写法与删改重组见 `governing-agents`。所有改动遵守 `AGENTS.md` 的执行原则。

## 语言与事实

- 以简体中文为主要语言；项目名、协议名、技术术语、命令和代码标识保留英文。
- 只写可验证的事实：公开仓库、可访问的链接、真实在用的技术。不虚构项目、指标、用户数量或演示地址。
- 涉及数字的组件（star、license、最近提交）先用 GitHub API 或 `gh` 核实，再决定是否展示；0 star 之类的空指标不写成亮点。
- 不确定的内容先核实；核实不了就删除，不保留占位描述。
- 全文使用 UTF-8，检查中英文标点、中文是否出现乱码，避免中英文之间缺少空格导致的挤压。

## 结构与文案

页面按「横幅 → 你好 → 技术栈 → 推荐仓库 → 过去一年贡献 → GitHub 统计 → 与我相关」组织，一条叙事线读下来即可建立完整印象。

- **你好**：标题只写 `你好`，不写「我是谁」。引言是「一段概述 + 一组带 emoji 的要点列表」：段落一句话说清身份与当前方向，列表逐条给出在做什么、为什么公开与下面能看什么，面向陌生人回答这三个问题。
- **技术栈**：按「编程语言」「工具与工作流」等维度拆成 `###` 子标题，每个子标题下只放对应的 Shields 徽章卡片，不再补一段文字复述各自分工。只列实际在用的技术，不写「仍在学习」「暂不列出」这类说明。
- **推荐仓库**：列表上方用 1–2 句说明列出的是什么、该怎么用，并把「全部公开仓库」与本仓库的 `ARCHITECTURE.md` 指针并入同一句；列表本身按 `designing-visuals` 的「推荐项目列表样式」执行，列表下方不再补句。
- **过去一年贡献**：说明句写在图上方，只说明数据来源与标注样式（月份、星期标注由 `.agents/skills/designing-visuals/scripts/activity/add_labels.py` 叠加，样式与 GitHub 贡献图一致），正文不写具体日期，也不重复自我介绍。
- **GitHub 统计**：只说明卡片由本仓库 Actions 根据公开数据生成，不写「来自第三方服务」；全页唯一的降级说明放在本节。
- **与我相关**：只写持续更新的去向与做事方式，定位为对外链接区，不重复上文已说过的定位。

## 字数区间

各章节篇幅以本表为唯一标准，其他文档只引用、不重写：

| 位置 | 字数区间 | 附加约束 |
| :--- | :--- | :--- |
| 引言（「你好」正文） | 120–280 字 | 3–4 句：身份 + 当前方向 + 为什么公开 + 页面导航 |
| 技术栈 | 0 字正文 | 只用 `###` 子标题与徽章，子标题 ≤ 10 字 |
| 推荐项目·列表上方说明 | 40–90 字 | 1–2 句：说明 + 「全部公开仓库」与 `ARCHITECTURE.md` 指针，写在列表上方 |
| 推荐项目·条目 | 每条 ≤ 60 字 | 1 句，最多 1 个行内链接 |
| 过去一年贡献·说明 | 30–70 字 | 1–2 句，只写数据来源与标注样式 |
| GitHub 统计·说明 | 30–70 字 | 1–2 句，含全页唯一的降级说明 |
| 与我相关 | 2 条，每条 ≤ 45 字 | 列表 |
| 全文正文合计 | 250–500 字 | 不含 HTML、URL 与徽章 |

写作要求：

- 写给人看：面向新人、陌生人、招聘方，用完整句子说明「做什么、为什么、怎么用」。
- 每个章节保持短小，能用一句话说清就不用两句；同一件事只在一个章节出现一次。
- 不写「基于 XX 技术」这类空话；项目条目要落到可验证的动作或产出。
- 不用口号收尾，也不写「欢迎交流」「保持好奇」这类没有信息量的句子；有具体去向就用链接和事实代替。
- 超出字数区间时先删重复，再压缩句子，不为凑长度补内容。

## 标题规范

标题的语言、emoji 与层级规则见 `writing-chinese` 的「标题」一节，本技能不重复定义。

## 可访问性与链接

- 所有图片都要有描述准确的 `alt` 文本；装饰性图片也要说明它展示了什么，不能留空。
- 横幅的 `alt` 描述画面与动效本身（「远处青山隐在晨雾里，溪流自山谷蜿蜒流出，两岸草地与石块上开满粉色、黄色与紫色小花，右侧树影层叠，天空与水面带柔和渐变，水面波光与花影缓慢流动」），不写「横幅」「装饰图」这类空指代，也不在 `alt` 里复述身份或方向。
- 链接文字说明目标，不使用「点击这里」「详见此处」这类无指向的措辞。
- 依赖第三方服务（徽章、统计图、动态图片）时，必须同时提供文字说明或替代链接，保证服务不可用时页面仍然可读；全页只在「GitHub 统计」保留一次降级说明，其他章节不复述。

## 检查清单

- 逐条核对事实：仓库存在、链接可访问、技术确实在用、指标与 API 一致。
- 逐段核对字数区间表，确认每处都在区间内，超出的先删重复再压缩句子。
- 检查是否有跨章节重复的表述，能合并就合并。
- 检查标题符合 `writing-chinese` 的标题规范。
- 检查推荐项目符合 `designing-visuals` 的「推荐项目列表样式」，说明与指针在列表上方、列表下方不补句。
- 检查每个 `<img>` 都有 `alt`，每个链接文字都能独立表意；贡献图的 `alt` 说明月份/星期标注与颜色含义。
- 确认文件编码是 UTF-8，中文没有乱码。
