# 注释格式规范

本文件承载 TOML、YAML、Lua、Python 注释的通用原则与各语言格式语法；措辞与「为什么」原则见本技能 `SKILL.md` 的「注释」一节，来源链接见同目录 `standards-sources.md`。

## 通用规则

适用于 TOML、YAML、Lua、Python 的全部注释，各语言语法见下文，以下原则共用：

- 文件头部用一段注释说明文件用途与使用方式，再进入内容；不写作者、日期等易过期信息。
- 注释与被说明的代码紧邻，放在代码上方；行尾注释仅用于极短补充。
- 不重复代码或相邻注释已表达的信息；同一事实只在一处注释。

## TOML（config.toml）

- 文件头为一段连续 `#` 注释块，空行分隔各主题；字段注释写在字段上方，先讲默认行为，再讲如何覆盖。
- 注释中给示例值时用该字段的真实语法（如 `python = "C:/path/to/python.exe"`），并标注「不要提交该行」这类使用边界。
- 路径一律正斜杠，并在文件头注明原因（避免 TOML 转义）。

## YAML（_quarto.yml、工作流）

- 每个步骤或非显然配置项上方写一行 `#` 注释说明目的；步骤名已自明的不再注释。
- 注释说明「为什么这样做」，尤其是为绕开工具默认行为而加的配置（如最小模板避免输出顶部空行）。

## Lua（过滤器）

- 文件头用 `--` 注释说明过滤器职责与输入输出。
- 每个函数上方用一段 `--` 注释说明用途与关键约定（如列宽换算规则）。

## Python（脚本）

- 可执行脚本首行固定为 `#!/usr/bin/env python3`（Unix 与 Windows 启动器均可识别的可移植 shebang），其后才是模块 docstring；仅被 import 的库模块可不写 shebang。
- 模块 docstring：先一句话说明职责，再写背景（为什么存在这个脚本）与用法示例（命令行形式）。实际调用仍以根目录 `config.toml` 的 `python` 字段为准，不依赖 PATH 上的 `python3`。
- 公共函数写 docstring：一句话职责 + 参数/返回值仅在含义不自明时说明。
- 行内注释解释常量数值、正则与边界条件的「为什么」（如「对齐 GitHub 贡献图：字号 10」）。

## 检查清单

- 每个被修改的文件：文件头说明用途、注释紧邻代码、无死代码注释。
- 注释为完整中文句子；格式语法符合上面对应语言的小节。
